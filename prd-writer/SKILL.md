## 一、触发词（trigger）

`/prd-writer`

* 触发：写 / 生成 / 补充 / 修改 PRD，把明确需求整理为 PRD
* 不触发：需求分析、UI 设计、技术方案 / 接口 / 数据库设计、代码实现

---

## 二、一句话描述（description）

基于已明确的需求信息，严格按照 `reference/prd-template.md` 生成标准 PRD。

> 忠于需求，不脑补；描述业务，不预设技术；一个信息只定义一次；规则即验收。

---

## 三、输入约定（inputs）

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| 需求信息 | ✅ | 需求分析、原型标注、已有 PRD 或用户明确提供的需求 |
| 参考 PRD | ⬜ | 仅用于参考表达风格 |
| 输出目录 | ⬜ | `--output-dir=<dir>`；默认输入文件同目录 |

至少应明确：需求场景（谁、什么情况、要解决什么）、本期涉及哪些页面、每个页面的功能范围。

信息处理：

* 影响核心方案 → 询问用户
* 不影响整体撰写 → 写入「待确认事项」
* 信息冲突 → 以用户最新明确说明为准
* 未明确内容 → 禁止自行假设

---

## 四、执行步骤（steps）

1. **读取需求**：提取需求场景、涉及页面、业务规则及待确认项。
2. **加载模板**：读取 `reference/prd-template.md`，以其作为唯一结构和内容粒度标准。
3. **拆页面**：按原型 / 菜单页面拆分，一个页面 = 一个 `##` 章节。不按按钮、组件或接口拆分。
4. **定页面类型**：套用对应骨架，类型不写进标题。

    | 类型 | 判断依据 | 主体章节 |
    | --- | --- | --- |
    | 列表型 | 筛选条件 + 数据表格 + 行内操作 | 筛选 / 列表说明 / 操作说明 / 其他说明 |
    | 详情型 | 汇总数据 + 明细列表 | 汇总说明 / 明细列表 / 页面操作 / 其他说明 |
    | 表单型 | 录入或配置字段 | 分组章节（可多个）/ 提交与校验 / 其他说明 |

5. **生成 PRD**：页面顺序与用户操作顺序一致；字段口径、状态定义、操作范围逐条写明。
6. **清理与自检**：先删掉全部 HTML 注释与未替换的占位文本，再按「五、写作约定」逐条比对：

    | 组 | 检查点 |
    | --- | --- |
    | 版式 | 层级三级 · 缩进 4 空格 · 无手写 `a.` `I.` · 分隔行 `\| --- \|` · 分割线仅页面之间 · 加粗只包名称 · 文案用「」 |
    | 结构 | 页面齐全且标题无类型后缀 · 需求场景一行斜体 · 表格挂在条目下 · 空节已整节删除 |
    | 内容 | 每条可转测试场景 · 无「按原逻辑」类表述 · 口径已写明 · 自动类三件事齐全 · 归属未越节 |
    | 干净 | 无 `<!-- -->` · 无未替换的模板占位符（`<...>`、模板中的 `YYYY-MM-DD`） · 无独立成行的「无」 · 未确认信息未写成规则 · 与「待确认事项」无冲突 |

---

## 五、写作约定（style）

本节是全 skill 的**唯一规则来源**。模板只给骨架与粒度示例，不重复定义规则。

### 骨架

页面顺序与用户操作顺序一致，页面之间用 `---` 分隔，其余位置一律不用。

* 一个页面一个 `##` 章节；标题只写页面名，不加「页面」二字、不标骨架类型
* 页面骨架固定三种，不混用（列表型章节里不出现「汇总说明」）；不自行增删一级章节
* 条件章节无内容时整节删除，不写「无」、不留空标题、不为完整性扩写
* 不单独设验收章节 —— 每条规则本身就要写成可直接转测试场景的口径

文档头固定四段，顺序不可换：

```text
# <需求名称> PRD           ← 标题
> 版本 v1.0　·　日期 YYYY-MM-DD   ← 版本行
*需求场景：<一整句话>*       ← 紧跟版本行，不设 ## 标题
## 变更记录                ← 全局，按版本倒序

## <页面一> … ## <页面N>    ← 页面之间用 --- 分隔

## 待确认事项               ← 全局，按需
```

### 层级

固定三级，缩进 4 空格：一级 `###` 标题，二级有序列表 `1.`，三级圆点 `-`。

```text
### 一、章节标题
1. 条目
    - 并列分支 / 补充说明

5. 行内交互 —— 点击「重试分账」
    - 二次确认：弹确认框，标题为「确认重试分账？」
    - 确认后：提示「订单 {订单号} 已提交重试分账」
```

* 二级写 `1.`、三级写 `-`，是为了两层渲染后一眼可辨 —— 都写 `1.` 时渲染出来都是「1. 2. 3.」，只能靠缩进分辨
* 不手写 `a.` `b.` `I.` —— 它们不是 Markdown 列表标记，查看器会把这些行当成上一层的续行，整块合并成一个段落
* 三级不够用时不继续嵌套：把上级名称用 `——` 并入下级首行（见上面 `5.`），或改用表格
* 编号在各自章节内从 `1.` 重新开始；跨节引用用「章节号 + 数字路径」，如「一、2.1」指「一、汇总说明」下第 2 条第 1 项

### 句式

* 字段 / 规则统一用 `名称：说明` 冒号式，冒号后直接写结论
* 必选性用「必选」「非必填」，不用「必须填写」「可选填」
* 选项值、状态值、按钮文案、提示文案一律用 `「」` 包裹
* 条件分支写成 `若…，则…` / `若…，展示…`
* 一个条目只表达一个判断，多个判断拆成子项，不合并成长句
* 涉及金额、比例、数量、时间、状态、生效范围、历史数据、重试的，必须写明对应口径
* 需要强调的补充或变更用 **加粗**；版本内追加的细节直接成行写「X月X日补充：……」

### 版式

* 并列项达到 3 条以上时优先用表格 —— 状态定义、取值枚举、校验规则、汇总口径
* 表格缩进 4 空格挂在所属条目下，前后各留一个空行；圆点子项紧跟父条目，中间不留空行
* 父条目只有子项、自身没有正文时，名称后不加标点；名称后还有正文再接子项时，用「：」收尾
* 表格分隔行统一写 `| --- |`，不按列宽拉长

### 字重

* 每条 `名称：说明` 里，冒号前的名称加粗，冒号后的说明保持常规 —— 二级、三级一视同仁
* 名称后若还有括号补充，括号部分不加粗：`**列说明**（按从左到右的顺序）：`
* 加粗只包住名称，不包整句；选项值、状态值、提示文案仍靠「」区分
* 同一行不出现两处以上加粗

### 归属

同一内容只写一处，写之前先确定它属于哪一节：

* 单字段的取值校验 → 跟着字段走（写在字段条目的子项里），不写进「提交与校验」
* 跨字段、跨行、跨成员的校验 → 「提交与校验」
* 明细行内的操作 → 写在该页的「明细列表」里，不写进「页面操作」
* 「自动带出 / 自动拉取 / 自动计算」的字段 → 必须写清 ① 数据来源 ② 刷新时机 ③ 取不到时的表现
* 「其他说明」只收三类 —— 范围外说明、跨节整体行为（排序 / 分页 / 空态 / 权限 / 数据来源）、版本内补充
* 版本级变更 → 文档头「变更记录」表；版本内追加的细节 → 正文「X月X日补充：……」

### 禁止

* 禁止「按原逻辑」「正常处理」「合理处理」「视情况处理」等无法执行的描述
* 禁止为凑完整而生成无依据的性能指标、技术难点或测试用例
* 禁止在正文写技术实现（数据库、接口、架构、代码）

---

## 六、输出契约（output）

| 项 | 要求 |
| --- | --- |
| 格式 | Markdown `.md` |
| 模板 | 严格遵循 `reference/prd-template.md` |
| 页面拆分 | 一页一节；类型取列表型 / 详情型 / 表单型之一，不写进标题 |
| 待确认内容 | 未确认的信息统一进入「待确认事项」，不写进正文 |
| 技术实现 | 默认不包含数据库、接口、架构或代码方案 |
| 注释 | 模板的 HTML 注释与示例一律不进入输出 |
| 新建文件 | 默认不覆盖原文件 |

默认文件名 `<需求名称>-PRD-YYYYMMDD.md`。

输出目录优先级：用户指定 `--output-dir` → 输入文件所在目录 → 无文件时直接输出 Markdown。
