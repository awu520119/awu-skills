## 适用范围

用于将需求分析、原型标注、已有 PRD 或用户明确说明整理、补充或修订为业务 PRD。不用于需求调研、UI 设计、技术方案、接口/数据库设计或代码实现。

> 忠于需求，不脑补；描述业务，不预设技术；围绕本次变化；规则即验收。

默认只描述本次新增、调整及其必要影响，不主动补齐整个页面的规格。既有能力仅在理解本次变化所必需时补充。用户提供已有 PRD 或风格样例时，沿用其有效结构与表达习惯；没有样例时使用内置模板。

## 输入与处理

读取用户提供的需求资料、相关原型和已有 PRD。至少确认需求场景、涉及页面/业务对象及本期功能范围。

- 信息冲突时，以用户最新的明确说明为准。
- 缺失信息会改变本次业务结果、金额、权限或操作路径，且无法从资料中确定时，优先向用户确认；可独立完成的部分继续整理，未决问题列入「待确认事项」。
- 本次未调整的既有细节不主动扩写，不因其缺失而追问或列入待确认事项；只有资料明确支持时，才将既有行为写入正文。涉及本次变化的未知规则不得自行假定。
- 未明确内容不得补造为正式规则；参考 PRD 只用于结构和表达风格，不复制无关业务。

## 写作流程

1. 提取本次变化涉及的需求场景、页面/业务块、字段、状态、动作、必要边界与待确认项。
2. 新建文档时读取 [PRD 模板](reference/prd-template.md)，按实际内容裁剪；修订已有文档时保留原有结构，不机械重套模板。
3. 按用户操作或业务阅读顺序划分章节。一个页面可按筛选、列表等业务块拆章；相关列表和详情也可放在同一模块下。修改已有文档时保留原层级，除非本次内容确需调整。
4. 将本期涉及的字段、展示规则、校验、权限、状态变化和二次确认写成可直接验证的业务口径，不为追求完整而增加未涉及的规则。
5. 输出前按下方自检项清理注释、示例和占位符。

## 文档骨架

完整骨架仅维护在 [PRD 模板](reference/prd-template.md) 中。

- 新建文档使用标题、版本日期、斜体需求场景、变更记录和业务章节；需求场景紧跟版本行，不另设章节。
- 章节名称按实际业务命名，使用 `##` 和按需添加的 `### 一、…`、`### 二、…` 分组；单一业务块可直接从 `1.` 开始。
- 仅在确有未决问题时添加文末 `## 待确认事项`；无内容时不保留空章节。
- 变更记录按版本倒序；新建首版保留「初版」一行。分隔线按阅读需要使用，不强加。

## 修订与关联检查

- 修改已有 PRD 时，检查文档头版本、日期、最新变更记录及需求场景是否与本次内容一致；有既有版本约定时沿用，不机械重置为 v1.0 或改成当天日期。用户指定新版本时同步文档头与记录；未指定时不擅自升级版本或声称已发布，必要的版本归属问题在交付说明中指出。
- 检查用户提供资料中与本次变化直接关联的同名字段、权限、周期、公式和历史数据口径；不扩大为全量审计。
- 本文直接相关且依据明确的内容同步修订。其他文档存在冲突时，在交付说明中指出文件和位置；未获授权不跨文档改动。业务含义不确定时向用户确认，不静默选择一种解释。

## 表达与排版

- 正文用有序列表逐条表达规则；同一组内从 `1.` 开始。补充、条件和并列分支缩进 4 个空格，用 `-` 表达。
- 字段、规则、状态和操作采用 `**名称**：说明`；名称后可附「（补充）」而不加粗。父项只有子项时可用 `**名称**：`。
- 选项值、状态值、按钮、页面页签、提示与确认文案均用「」；变量保留为 `{变量名}`，例如「该点分成合计 {合计}%」。
- 条件必须写清触发条件和结果，使用「若…，则…」或「…时，展示…」。本次涉及金额、比例、数量、时间范围、周期、生效范围、历史数据或重试变化时，明确相应口径。
- 默认采用有序列表和缩进分支；需要横向比较多项属性时再用表格，不按条目数量决定。表格紧随所属条目，表头、分隔行和数据行的列数保持一致。
- 同一业务块内避免重复定义：字段内校验跟字段走，跨字段/跨行校验放在相应业务块，明细行操作跟明细走。独立交付的页面或文档允许重复必要口径，确保一致并保留各页面的权限、展示等差异；不强制读者跨文档查找才能理解本页规则。
- 本次新增或调整自动带出、计算、刷新行为时，写清决定业务结果所需的数据来源和触发条件；刷新时机、无结果展示或能否继续操作会影响本次行为时才补充。未涉及的既有细节不强行补齐。

## 禁止与自检

不得用「按原逻辑」「正常处理」「合理处理」「视情况处理」替代本次变化的具体规则；禁止无依据补充技术实现、性能指标或测试用例。

输出前检查：

| 检查项 | 要求 |
| --- | --- |
| 结构 | 新建文档按模板裁剪，修订文档保留有效结构；只保留有内容的小节和待确认事项 |
| 口径 | 本次变化可验证，必要条件、范围、结果和文案明确；未扩写无关既有细节 |
| 一致性 | 正文与需求场景、版本记录一致；关联口径的冲突已处理或明确指出，未擅自解释 |
| 清洁 | 无 HTML 注释、示例、`<...>`、未替换日期或独立成行的「无」 |
| 边界 | 未确认信息不写成规则；不包含数据库、接口、架构或代码方案 |

## 输出

默认输出 Markdown 文件，文件名为 `<需求名称>PRD-YYYYMMDD.md`；优先写入用户指定目录，否则使用输入文件所在目录；无输入文件时使用当前工作目录。新建文件默认不覆盖原文件；补充已有 PRD 时只改动用户指定章节及其直接相关规则。
