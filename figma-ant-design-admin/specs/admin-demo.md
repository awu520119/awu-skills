# 形影随拍后台 Demo 规范

## 1. 定位

- 用于产品演示、需求评审和交互验证，不默认承担生产系统职责。
- 默认纯前端，业务数据放在 `src/mock/`；不要调用真实接口。
- 需求明确要求接入已有接口时，先遵循目标仓库的数据层和权限约定。
- 以设计稿信息架构和业务行为为准，不为了“丰富页面”增加无关数据、图表、操作或导航。

## 2. 技术栈与目录

| 维度 | 规范 |
| --- | --- |
| 框架 | React + TypeScript |
| 构建 | Vite |
| UI | Ant Design + `@ant-design/icons`，中文语言包 `zh_CN` |
| 路由 | React Router，使用 Hash 路由以便静态部署 |
| 数据 | 本地 TypeScript Mock；按模块放在 `src/mock/` |
| 主题 | 根节点 `ConfigProvider`，统一管理全局 Token 与组件 Token |

模板目录：

```text
src/
├── mock/          # Mock 数据和类型
├── pages/         # 页面
├── App.tsx        # 后台框架与路由
├── main.tsx       # 应用入口、中文语言、主题
├── styles.css     # 全局基础样式和少量作用域覆盖
└── theme.ts       # Figma Token 到 Ant Design Token 的映射
```

新增复杂业务时，可按需增加 `components/`、`api/`、`hooks/` 和 `utils/`，不要预建空目录。

## 3. 规范优先级

冲突时按以下顺序处理：

1. 用户当前需求和验收标准。
2. 目标项目已经存在的组件、路由、数据和样式约定。
3. 当前页面完整尺寸的 Figma 导出、测量 CSS、组件状态图和 Variables。
4. 本规范记录的稳定设计规则。
5. 当前安装版本的 Ant Design 默认行为。

Figma CSS 只用于确认重复尺寸和语义 Token。不要复制画布绝对 `left`、`top`、矢量内部结构、翻转变换或单个图层固定文本宽度。

## 4. 设计 Token

### 颜色

| 语义 | 数值 | Ant Design 映射 |
| --- | --- | --- |
| 主文字 | `#303338` | `colorText` |
| 次文字 | `#696C70` | `colorTextSecondary` |
| 三级文字 | `#8F9499` | 表头、辅助说明、元信息 |
| 占位与弱化文字 | `#B3B8BF` | `colorTextPlaceholder` |
| 产品主色 | `#2776FF` | `colorPrimary` |
| 危险与错误 | `#FF4D4F` | `colorError` |
| 成功 | `#52C41A` | `colorSuccess` |
| 一级边框 | `#D7DAE0` | `colorBorder` |
| 分割线 | `#E9EBF0` | `colorSplit` |
| 页面背景 | `#F2F4F7` | `colorBgLayout` |
| 小区块背景 | `#F5F7FA` | 局部弱化背景 |
| 表头背景 | `#FAFAFA` | `Table.headerBg` |
| 容器背景 | `#FFFFFF` | `colorBgContainer` |

### 字体

- 字体栈：`HarmonyOS Sans SC`、`PingFang SC`、`Microsoft YaHei`、系统无衬线字体。
- 正文和控件：14px、字重 400、行高 22px。
- 表头和中等强调标签：14px、字重 500、行高 22px。
- 弹窗和抽屉标题：16px、字重 700、行高 24px。
- 页面顶栏标题：18px、字重 500、行高 24px。
- `DIN` 只用于设计稿中明确出现的指标型数字。

### 尺寸与间距

- 标准控件高度 32px，控件圆角 2px。
- 普通内容卡片圆角 4px，默认内边距和区块间距均为 16px。
- 表头和数据行高度 48px，单元格左右内边距 12px。
- 分页项为 32 × 32px。
- 常用间距梯度：2、4、6、8、10、12、16、20、24、32px。
- 不要只根据 Figma CSS 中某个数值出现次数多，就把它定义为全局 Token。

## 5. 后台整体布局

- 支持 1440、1600 和 1920 宽度的桌面画布，使用 Flex 自适应，不制作多个固定宽度版本。
- 展开侧栏宽 220px，收起侧栏宽 80px；背景 `#000000`，左右内边距 16px，顶部内边距 28px。
- 顶栏高 58px，左右内边距 24px，背景与页面同为 `#F2F4F7`。页面标题放在顶栏左侧，账号放在右侧。
- 主内容区左右和底部边距为 20px。
- 使用 `Layout.Sider` 的 `width={220}` 与 `collapsedWidth={80}`。
- 收起按钮固定在侧栏底部，不占用页面标题区域。收起后只显示 48px 品牌图标和一级菜单图标。
- 菜单选中项与展开项根据当前路由计算，不得永久写死。
- 一级菜单约高 42px；二级菜单高 44px，左内边距 38px。
- 选中菜单背景为 `#3F86FF`，普通深色菜单文字为 `rgba(255,255,255,.8)`。

### 截图校准基线

以下规则来自 1440 × 900、1600 × 900 和 1920 × 900 完整页面截图，并与导出的 Figma CSS 中重复值交叉确认：

- 1440 宽展开态：侧栏占 220px，内容起点为 220px；白色主体距离内容区左右各 20px。
- 1440 宽收起态：侧栏占 80px，主体随之扩展，不保留 220px 的空白占位。
- 标准页面从 `y=58px` 开始；列表主体通常延伸到距离视口底部 20px。
- 单一列表页使用一张满高白卡；订单类复合页使用“64px 筛选条 + 12px 间隔 + 106px 指标条 + 12px 间隔 + 表格卡”。
- 页面主体不使用外阴影和大圆角；白卡圆角维持 4px，弹出菜单可使用轻阴影。
- 以截图中可见的容器边界、留白和响应关系为准；高分辨率导出图可能按 2× 或 3× 缩放，先换算 CSS 像素再实现。

## 6. 组件规范

| 场景 | 组件 |
| --- | --- |
| 应用框架 | `Layout`、`Sider`、`Header`、`Content` |
| 导航 | `Menu`、`@ant-design/icons` |
| 查询 | `Form`、`Input`、`Select`、`DatePicker`、`Cascader` |
| 数据列表 | `Table`，使用稳定 `rowKey` |
| 状态 | `Tag`、`Badge`、`Progress` 或语义文字 |
| 详情 | 独立路由或 `Drawer` |
| 短确认 | `Popconfirm` 或 `Modal.confirm` |
| 带备注确认 | 受控 `Modal` + `Form` + `Input.TextArea` |
| 上传 | `Upload`，包含预览、失败和移除状态 |
| 反馈 | `App.useApp()` 提供的 message、notification、modal |

需要键盘、焦点、弹层或校验能力时，必须使用 Ant Design 组件，不使用样式化 `div` 仿制。

## 7. 页面模式

### 列表页

结构依次为顶栏、白色内容卡片、可选标签页、筛选区、表格、总数与分页。普通管理列表把筛选区和表格放在同一张满高白卡中；订单等存在汇总信息的页面拆成筛选条、指标条和表格卡。查询和重置同步更新筛选条件与页码。行操作使用蓝色文字，危险操作使用语义红色并二次确认。

- 筛选条高约 64px，左右内边距 16px，控件间距 12px；主要操作可右对齐。
- 标签页与表格放在同一张卡内，标签栏高约 52px；右侧搜索框常用宽 260px。
- 表格卡底部左侧显示总数，分页右对齐。宽屏优先展示完整列；窄屏保留操作列并启用横向滚动。
- 订单指标条高约 106px，左右内边距 24px；图标块 56 × 56px，业务计数在左、金额关系在右，中间使用虚线分隔。

### 左右分栏页

左侧分组或树形区域固定约宽 220px，背景 `#FAFAFA`；右侧自适应并使用 36px 左右内边距。两栏整体位于同一张满高白卡内，不在左右区域外再套独立卡片。左侧选中状态必须驱动右侧标题、查询和数据变化；选中项背景使用浅蓝，右侧边缘显示主色强调线。分栏折叠按钮位于边界中部，收起后提供明确的恢复入口。

### 表单与抽屉

- 使用 `Form` 作为状态与校验边界，不手动绘制标签、必填符号和错误提示。
- 简洁时间线或运行详情抽屉使用约 580px；订单详情使用 800px；多步骤复杂表单使用 800–824px；账单等密集详情使用 960px。1440 视口下不得让普通详情抽屉超过页面可读范围。
- 抽屉头部高 56px、内边距 16px 24px，可使用白色到 `#D8E6FF` 的规范渐变。
- 抽屉底部操作栏高 56px、内边距 12px 24px，操作右对齐；主体独立滚动。
- 打开不同记录时重置临时表单状态。
- 多步骤抽屉的步骤条位于内容顶部，三步场景横向均分；表单内容和固定底栏之间必须留出安全间距。
- 可重复配置块使用白色卡片和极浅阴影，卡头约 56px；拖拽、折叠和删除操作都必须可见且可操作。

### 弹窗与气泡确认

- 不带输入的标准确认弹窗宽 440px，带备注或文本域时宽 600px。
- 确认弹窗内边距 32px 32px 24px，警告图标 22px、颜色 `#FAAD14`。
- 遮罩为 40% 透明度黑色。
- 气泡确认示例宽 300px、内边距 16px、圆角 2px。
- 不可逆操作必须说明对象和影响，提交期间禁止重复操作。

## 8. Mock 与交互

- Mock 数据放在独立模块中，页面通过导入或轻量数据函数使用，避免把大量数据写进 JSX。
- 查询、重置、分页、查看详情和危险操作必须可实际操作。
- 表格按场景提供加载、空数据、错误或禁用状态。
- 表单提供校验、提交中、成功和失败反馈。
- 弹窗与抽屉关闭后应正确清理临时状态，重复打开行为一致。
- 不增加登录、权限、埋点、国际化框架或状态持久化，除非演示需求明确需要。

## 9. 样式边界

优先顺序：现有公共组件 → `ConfigProvider` 全局 Token → 组件 Token → 页面作用域 CSS。

- 不使用很深的 `.ant-*` 全局选择器链。
- 相同颜色、圆角、字体和间距优先通过 Token 管理。
- 不引入营销页常见的大圆角、渐变卡片和超大留白，除非设计稿明确存在。
- 长中文内容要明确选择换行、截断或 Tooltip，不能依赖偶然溢出。

## 10. 验收

- 页面框架、信息层级、表格密度和弹层类型符合设计依据。
- 中文标签、表格列、状态和操作顺序符合需求。
- 所有可见操作形成可演示闭环，不存在装饰性假控件。
- 导航、筛选、分页、表单、弹窗和抽屉可重复正常操作。
- `npm run check` 与 `npm run build` 通过。
- 按目标桌面视口渲染，检查对齐、换行、截断、溢出、固定区域和弹层高度。
- 缺少完整画板时，明确说明还原限制，不声称达到像素级一致。
