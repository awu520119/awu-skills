# 形影随拍后台 Demo 规范

本规范提炼自 `xiaomifeng_premium` 的成员、推广方、订单、任务、结算列表，订单详情抽屉、账期详情页和新增编辑抽屉。先判断目标项目已有模式及设计稿，再选用相应做法；业务专属的状态章、金额摘要、媒体区和蓝色渐变摘要不作为通用组件。

## 定位与优先级

Demo 用于演示和交互验证，默认纯前端、使用本地 Mock。冲突时依次遵循：用户需求、目标项目约定、完整设计稿及测量信息、本规范、Ant Design 默认行为。

Figma CSS 只用于确认重复尺寸和语义 Token；不要复制画布绝对坐标、矢量内部结构或单图层固定文本宽度。

## 技术基线

- React + TypeScript + Vite + Ant Design，入口使用 `ConfigProvider` 和 `zh_CN`。
- 静态部署使用 Hash 路由和 Vite 相对资源路径。
- 页面放在 `src/pages/`，Mock 放在 `src/mock/`，稳定设计值放在 `src/theme.ts`。
- 仅在确有复用需求时增加 `components/`、`hooks/` 或 `utils/`。

## 视觉基线

| 语义 | 数值 |
| --- | --- |
| 主文字 / 次文字 / 弱文字 | `#303338` / `#696C70` / `#8F9499` |
| 主色 / 危险 / 成功 | `#2776FF` / `#FF4D4F` / `#52C41A` |
| 边框 / 分割线 | `#D7DAE0` / `#E9EBF0` |
| 页面 / 表头 / 容器背景 | `#F2F4F7` / `#FAFAFA` / `#FFFFFF` |

- 字体栈：`HarmonyOS Sans SC`、`PingFang SC`、`Microsoft YaHei`、系统无衬线字体。
- 正文与控件 14px/22px；弹层标题 16px/24px；页面标题 18px/24px。
- 控件高 32px、圆角 2px；白卡圆角 4px、内边距 16px；表格行高约 48px。
- 常用间距为 8、12、16、20、24、32px。页面主体不用大圆角、外阴影或营销式留白。

## 页面框架

- 适配 1440、1600、1920 宽桌面画布，使用 Flex 自适应。
- 侧栏展开 220px、收起 80px，背景黑色；收起按钮固定在底部。
- 顶栏高 58px、左右内边距 24px；主内容左右和底部留白 20px。顶栏背景沿目标项目既有布局，premium 示例与页面底色一致。
- 菜单状态由当前路由计算。展开侧栏后一级菜单约高 42px，选中背景 `#3F86FF`。
- 高分辨率导出图先换算为 CSS 像素，再校准容器边界和响应关系。

## 常用页面模式

### 列表页

- 先看页面信息量。简单列表可用一张满高白卡，依次放筛选、表格和分页；premium 的成员、推广方、任务页把筛选和列表分成两张白卡，卡间约 12px，便于突出列表标题和主操作。汇总数据确有业务作用时再加摘要卡，不为凑版式增加卡片。
- 分卡模式下，筛选卡使用约 `12px 16px` 内边距、至少 64px 高；列表卡使用左右 16px 内边距，标题工具行约 56px 高并以浅分割线隔开表格。标题通常 16px/24px、字重 500；新增等主操作放工具行右侧，状态页签可占工具行左侧。表格和分页留在同一卡内。
- 筛选项横排、约 8–12px 间距，空间不足时换行。占位符写清字段，关键词输入可用「查询姓名、账号、手机号」这样的实际范围；下拉框用字段名。筛选默认即时生效，只有设计稿或查询成本要求时再增加显式查询按钮。
- 重置用带 `ReloadOutlined` 的蓝色链接按钮，必须清空关键词、选择、日期及页签等当前筛选状态；有上下文锁定条件时，明确区分页面筛选重置与退出上下文。空状态给出与数据范围一致的说明。
- 用 Ant Design `Table` 保持表头、行距和分页一致。主信息在首行，编号、归属、规则等次信息用 12px/18px 弱文字另起一行；状态用 `Tag`，金额或数量按语义强调。长文本优先设置列宽、截断与悬浮完整值，避免撑坏表格。
- 默认分页在表格底部，显示总记录数。宽屏优先展示完整列；列宽总和超过容器时设置匹配的 `scroll.x`。操作列固定在右侧并留足宽度，优先保留 Ant Design 原生固定列阴影；危险操作需要确认，并说明对象和后果。

### 详情页

- 信息需要持续查看、包含摘要与明细表时使用独立详情页。premium 账期详情使用顶部白卡承载返回入口、当前标题与辅助身份信息，面包屑行约 52px；下方按信息关系放摘要和明细卡。返回入口回到原列表上下文。
- 详情顶部先回答“正在看哪条记录、当前状态是什么”，再展示与决策有关的关键摘要。摘要卡只在有多项关键指标时使用；不要把业务专属的蓝色渐变、装饰图形或状态章复制到所有详情页。
- 主体用有标题的白卡或分节组织。账期示例的明细表标题行约 48px，表格放在标题下方；字段多时用 `Descriptions` 两列展示，标签使用次级文字，值保持可读。空值统一用「-」或项目既有规则，长编号与失败原因提供可查看的完整内容。
- 列表进入详情后应能返回原筛选或对象上下文；详情中的页签、范围筛选和次级链接须更新真实展示内容。

### 详情抽屉

- 信息适合在列表旁快速核对时使用右侧详情抽屉。普通详情约 580–640px；订单等字段多、含分节内容时约 800px，密集内容最多约 960px，最终按内容和画布宽度调整。
- 标题明确对象类型，如「订单详情」。正文独立滚动，按“概览 → 关联信息 → 过程/明细”分节；premium 订单抽屉正文左右约 28px，节间约 24px，以浅分割线区隔，节标题约 16px，可用细蓝竖线强调。`Descriptions` 标签用次级文字，正文不伪装成可编辑输入框。
- 只读详情无保存按钮；有独立业务动作时才使用底部操作区，并按权限和状态决定可用性。关闭后清理临时页签、展开项等状态；从详情打开关联对象时保持层级和返回路径清楚。

### 新增与编辑右抽屉

- 新增、编辑共用右抽屉及表单主体，标题按模式写「新增…」「编辑…」，打开时分别初始化默认值或当前记录。premium 的成员与推广方表单使用约 720px 宽；简单表单可更窄，复杂配置需保证字段不拥挤。
- premium 编辑抽屉的头部约 56px、内边距 `16px 24px`，采用浅蓝到白色的轻渐变；主体内边距约 24px并独立滚动；底部操作区内边距 `12px 24px`、顶部浅分割线，按钮右对齐，顺序为「取消」「保存」。仅在目标项目沿用该抽屉视觉时使用渐变头部。
- 表单按业务分组，组间约 24px；分组标题可用左侧 3px 蓝色竖线，标题下留约 12px。标签在控件上方，字段纵向间距约 12px；相关短字段可两列、列间约 16px，说明、上传、规则表等长内容占整行。必填星号、辅助说明、只读值和错误提示分别使用明确层级，错误就近显示在字段下方。
- 使用 Ant Design `Form` 处理常规值与校验；已有复杂配置若采用自有 `Field` 组件，须保持同样的标签、错误和键盘交互。不可编辑字段以禁用或只读状态呈现，并说明原因；编辑模式只锁定业务上确实不可变的字段。
- 保存前校验并在对应字段显示错误；成功后更新本地 Mock、关闭抽屉并让列表或详情反映新值。取消关闭时清理临时状态；重新打开不同记录时不沿用上一次的输入、错误或上传结果。危险或不可逆变更另设确认，不把保存按钮当作确认流程。

### 分栏

- 左侧分组区约 220px，右侧自适应；两栏位于同一白卡内。
- 左侧选择必须驱动右侧标题和数据。折叠后提供明确的恢复入口。

### 其他弹层

- 标准确认弹窗约 440px；带文本域时约 600px。不可逆操作说明对象和影响，并防止重复提交。

## 实现与验收

- 需要键盘、焦点、校验或弹层能力时使用 Ant Design 组件，不用样式化 `div` 仿制。
- 优先级：已有公共组件 → 全局 Token → 组件 Token → 页面作用域 CSS。
- 所有可见操作形成演示闭环；不为丰富页面增加无关模块或假控件。
- 检查导航、查询、分页、详情返回、表单和弹层的重复操作，以及换行、截断、溢出和固定区域。重点核对 1440px 画布中的筛选换行、固定操作列、抽屉表单两列和底部按钮。
- `npm run check` 与 `npm run build` 必须通过。设计资料不完整时说明还原限制。
