# 产品判断

帮助用户做出当前最合理的产品决策，并指出什么新证据会改变判断。先弄清问题和证据，再比较解决路径；分析深度与决策影响相称。尊重用户已确定的目标、范围和执行授权。

## 调用边界

- 用户要判断“值不值得做、先做什么、是否产品化、如何验证”时使用。
- 用户只要求落实已决定的方案时，完成该任务；仅在发现会实质影响结果的风险时简短提示，不强制重做完整产品判断。
- 用户仅要求产品方案、PRD 或页面设计时，不把本 Skill 的决策模板附加到交付物中。

## 判断方法

1. **定义问题。** 区分用户提出的功能、实际遇到的障碍和期望完成的任务。可用一句话表达：谁在什么场景下，因什么障碍无法完成什么任务，产生什么可观察的损失。信息不足时写成待验证的问题假设。
2. **审查证据。** 区分已观察事实、利益相关方陈述、推断和未知。优先看近期行为、现有替代做法、实际成本及已发生的业务影响；口头需求和未来使用意愿只能支持进一步验证。证据只适用于其来源和样本，不把单个客户的情况推断为整个市场。
3. **评估价值与时机。** 看发生频率、损失严重性、影响人群、战略相关性、用户价值、商业价值、实施与维护成本，以及为什么现在处理。没有数据的维度标为未知，不编造分数或数量。
4. **比较路径。** 同时考虑流程、运营、配置或人工解决；小范围原型或试点；完整产品建设。只展开与当前问题相关的选项，并考虑机会成本。
5. **找出关键不确定性。** 选择最可能改变决策的一个假设，给出成本相称的验证方法、观察指标、继续与停止条件。指标尽量连接行为变化、用户结果和业务结果，避免只用点击量或上线状态证明价值。
6. **检查反证。** 提出最有力的反对理由，并说明何种证据会推翻当前判断。理由数量取决于实际风险，不凑数。

需要访谈时，优先询问最近一次真实发生的情况、当时的做法和付出的成本，而非“以后会不会用”。

## 决策规则

给出一个当前决策；证据不充分时明确标注为暂定，不把未知写成否定证据。

| 决策 | 适用条件 |
| --- | --- |
| **BUILD** | 问题、价值及可行性已有足够证据，当前投入优于主要替代机会。 |
| **EXPERIMENT** | 机会有潜力，但关键假设尚未验证，且存在成本相称的验证方式。 |
| **DEFER** | 问题值得解决，但时机、资源或当前优先级不支持立即投入；说明重启条件。 |
| **REJECT** | 已有证据表明问题价值、战略相关性或解决收益不足；说明改变判断所需的新证据。 |
| **CUSTOM** | 值得满足特定客户或场景，但尚不宜抽象为通用产品能力；说明交付边界。 |

不能据现有信息判断时，先给出最合理的**暂定决策**和关键未知；只有这个未知会阻止有意义的下一步时，才向用户询问。

## 默认输出

简短任务默认按以下顺序回答，不机械铺开所有维度：

1. **当前判断**：一个决策及一句话理由；必要时标注“暂定”。
2. **依据**：最重要的事实、推断与未知，并说明关键证据的来源或局限。
3. **主要取舍**：最有力的替代路径或反对理由。
4. **下一步**：最小验证或执行动作、成功与停止条件，以及可能改变判断的新证据。

重大投入、多方案路线图或用户要求深入分析时，再展开各价值维度、机会成本、指标链与产品化路径。用户指定了交付格式时，优先遵守用户格式。

## 专项检查

- 涉及 AI 功能的投入判断时，读取 [AI 产品判断](references/ai-product.md)，重点检查效果门槛、失败成本、人审与单位经济性。
- 涉及多个客户需求的共性抽象或定制转产品时，读取 [产品化判断](references/productization.md)，重点检查共同任务、差异边界与边际交付成本。
