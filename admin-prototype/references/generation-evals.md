# 生成任务评估

修改 skill 路由、实施顺序或公共组件使用规则时使用。与模板测试区分：这里检查模型实际调用 skill 后的产物，不把同一个模板重复构建算成生成稳定性验证。

在隔离目录和新的会话中，用同一模型及配置执行下列任务，每项至少独立运行三次。保留请求、实际读取与执行记录、源码、最终 HTML 和浏览器报告。不要向被测会话提供预期实现或历史失败答案；不在用户业务项目中试验。

| 任务 | 请求示例 | 关键结果 |
| --- | --- | --- |
| 简单列表 | 用 admin-prototype 新建设备列表，包含编号、名称、状态，支持名称查询、状态筛选、重置和分页 | 统一搜索、总数、容量切换、筛选回首页、空结果 |
| 复杂列表 | 新建订单列表，含多组筛选、状态页签、可折叠统计、金额和右侧操作列 | 双视口不撑开页面、金额格式、分页可见、操作可达 |
| 编辑表单 | 为设备列表增加编辑抽屉，名称必填，保存后列表和再次编辑显示最新值 | 标准表单/抽屉、错误态、取消不保存、保存后重开 |
| 长文本详情 | 增加设备详情，显示长编号、长说明和多个分节 | 文本可读、标签对齐、无重复标题、抽屉不超视口 |
| 既有项目 | 在提供的旧风格项目中仅增加状态筛选；另一轮明确要求将该页面迁移到默认规范 | 两种意图采用正确基准，保留无关业务与文件 |

每次分别记录：是否采用正确设计基准、是否复用适用组件、公共参数是否生效、双视口布局是否通过、要求的业务闭环是否通过、是否如实报告未覆盖项。硬性结果逐项计通过/失败，颜色、对齐、密度通过实际截图审阅评分。汇总每项通过次数及具体失败原因，不用一个笼统“效果更好”替代证据。

先修复重复出现的具体问题，再调整指令或组件；不根据一个业务特例扩大所有任务的规则。大规模自动调用涉及额外费用时，按当前任务授权范围执行。
