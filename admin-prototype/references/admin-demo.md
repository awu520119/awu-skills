# 后台原型设计规范

本文件是后台页面的独立设计基线。无需读取历史项目、截图或其他技能；用户提供设计稿时按其校准。本规范中的尺寸均为 CSS 像素，截图分辨率不能直接当作控件尺寸。

## 使用方式与优先级

用户最新要求 → 目标项目明确约定 → 完整设计稿 → 本规范 → Ant Design 默认值。已有项目先沿用其组件和页面结构；未指定的部分使用本文件默认值。同一项目只使用一套间距、字体、颜色和组件密度。

原型默认 React + TypeScript + Vite + Ant Design、本地 Mock、中文组件文案、独立部署使用 Hash 路由及相对资源路径。嵌入单文件查看器的 `srcdoc` / Blob 上下文时，按发布页注入的 `__PROTOTYPE_INITIAL_ROUTE__`（或已有 hash）初始化 `MemoryRouter`，避免无有效 URL 基址时白屏；两种模式复用同一页面与导航。入口用 `ConfigProvider` 统一 Token；页面放 `src/pages/`，Mock 放 `src/mock/`，公共 Token 放 `src/theme.ts`。有复用需要再提取组件，不引入真实后端。

## 1. 视觉原则

- 适合日常操作的桌面管理系统：信息层级清楚、数据便于比较、操作位置稳定。默认黑色业务侧栏、浅灰工作区、白色业务容器和蓝色主操作。
- 一页一个清楚的业务标题；一个操作区域通常一个实心主按钮。用标题、留白、分割线组织内容，不为填满画布增加指标卡、插画或装饰。
- 不使用营销式大标题、大圆角、玻璃效果或卡片外阴影。浮层保留组件自带阴影，抽屉可用规定的浅渐变头部。
- 状态以文字配合颜色表达；金额只在关键支付金额或汇总时强调。媒体区、完成印章和业务摘要按内容需要使用。

## 3. 间距与几何

- 间距使用 4px 基准；常用 8、12、16、20、24、32px。不要逐个控件临时设置相近但不同的间距。
- 控件高 32px，按钮左右内边距 15px，图标与文字间隔 8px；小按钮高 24px，仅用于表格或紧凑区域。
- 控件圆角 2px、容器圆角 4px、标签圆角 2px。按钮、输入、下拉和数字输入同一行等高。
- 白卡默认内边距 16px；多卡间距 12px；分组间距 24px。无边框业务卡用背景区隔，避免重复套卡。
- 常规表格行高至少 56px、表头约 48px；紧凑表格行高至少 48px。多行内容可以自然增高，禁止裁切文字以凑行高。

## 4. 页面框架与响应

- 默认保留黑色业务侧栏：展开 220px、收起 80px，视口等高。品牌区高度约 148px，菜单区域可独立滚动；折叠按钮固定底部。导航选中状态由实际路由驱动，收起时提供菜单名称提示。
- 顶栏高 58px、左右内边距 24px，左侧页面标题，右侧账号等已有全局操作。顶栏与页面背景一致；没有业务能力的通知、返回空间等按钮不要为了仿图添加。
- 主体左右及底部留白 20px；单卡列表最小高度 `calc(100vh - 78px)`。主体 Flex 子项设置 `min-width: 0`，避免表格撑宽整个页面。
- 桌面验收宽度为 1440、1600、1920px。1440px 下优先让筛选区换行、表格内部横向滚动，不缩小文字、不移除侧栏。更窄视口按项目要求处理，默认不扩展为移动端设计。
- 表格的横向滚动留在表格内；复杂长列表可用固定表头和内部滚动，底部分页始终可到达。页面与弹层不得互相争抢滚动。
- 抽屉宽度不超过视口：使用类似 `min(720px, 100vw)` 的约束；窄于桌面宽度时两列表单可改为单列，保留内边距与底部操作。

## 5. 列表与工具区

按任务选一种结构，页面内不混用相互冲突的工具行：

| 模式 | 结构与适用情况 |
| --- | --- |
| 单卡列表（默认） | 同一卡内依次为筛选操作区、表格、分页；简单主题、成员等管理页 |
| 分卡列表 | 筛选卡至少 64px 高，约 `12px 16px` 内边距；下方列表卡含约 56px 标题工具行、表格和分页 |
| 业务摘要列表 | 只有确实需要汇总指标时，在筛选与列表之间增加摘要；状态页签位于列表上方 |

- 单卡工具区左侧筛选，右侧管理类次操作和新增主操作；横纵间距 12px，工具区距表格 20px。空间不足可换行，操作组靠右放到下一行。分卡模式的主操作放列表工具行右侧。
- 关键词搜索默认宽 224px，下拉默认 160px，日期范围约 260px；按内容可在 128–240px 范围调整下拉宽度。禁止为了塞进一行让控件内容不可读。
- 有搜索按钮的关键词输入在点击或 Enter 后生效；下拉可即时生效。没有搜索按钮时才采用即时关键词筛选；同一输入不要混用两种触发方式。
- 筛选项必须能识别字段；下拉选中后不清楚语义时保留字段标签或前缀。搜索范围写明，例如「订单号或手机号」。
- 重置为带刷新图标的蓝色文字按钮，清空页面筛选、关键词和筛选页签并回到第 1 页。改变筛选或每页条数时处理分页，避免落在空页。
- 状态页签高约 48px、选中蓝字与 2px 下划线，数量仅在有真实 Mock 统计时展示。

## 6. 表格与数据排版

- 使用 Ant Design `Table`。默认水平分割线、不显示全表网格；表头浅灰、次文字色，单元格左右 12px。悬停使用轻背景反馈。
- 序号列约 64px；状态列约 96px；名称列约 200–240px；手机号约 136px；时间约 176px；金额约 112px；操作按实际按钮宽度配置。宽度是起点，必须用真实长度验证。
- 文本左对齐，金额与可比较数量右对齐并使用等宽数字；金额同列统一小数位和单位，单位优先放表头。日期时间保持单行，格式一致。
- 名称、备注等长文本先设列宽再截断，以悬停完整值或详情补全；编号可复制，详情内允许换行。首列承载业务主信息时，不用通用“字段1”等占位内容。
- 次信息可另起一行用 12/18 弱文字，同一表格不要无规则混合单行、三行内容。缺失值统一 `--`，不能把 0 当作缺失。
- 状态用小号浅底描边标签，文字明确，图标可选；同一状态在列表和详情颜色相同。分类标签也用浅蓝描边，不用大面积彩色底。
- 所有列表的操作列必须固定右侧，横向滚动只移动数据列，操作组与表头位置不变；背景不透明并保留固定列边界提示。操作总数不超过 3 项时可直接展示；超过 3 项时必须把编辑、删除收进更多菜单，其余行内最多展示 2 项文字操作加更多入口。行内文字操作间距 16px、同为 24px 高且无多余水平内边距；更多图标使用主色，悬停和按下使用对应主色状态，图标按钮宽高 24px 并有名称。按实际动作数量预留足够操作列宽，不让按钮贴边或换行。危险动作确认框写明对象和后果。
- 宽表设置与列宽总和匹配的 `scroll.x`；不得用全局 `overflow: hidden` 隐藏列。分页在表格下方右对齐、上间距 16px，显示总条数；默认 10 或 20 条，业务页内一致。

## 7. 详情页与详情抽屉

- 信息需持续查看或含复杂明细时用独立详情页，顶部保留返回、对象标题与状态；返回恢复原筛选和分页。主体按摘要、关联信息、明细组织白卡，避免整页堆叠字段。
- 列表旁快速核对用右侧抽屉：普通详情 600px，密集订单详情 800px，确有需要可到 960px。正文左右 24–28px、节间 24px；宽度按内容选，不照抄截图像素。
- 抽屉头高至少 56px、内边距 `16px 24px`，浅蓝到白渐变；标题左对齐、关闭在右侧。正文独立滚动；有底栏时固定底栏，正文不能被遮挡。
- 两列 `Descriptions` 的标签为次文字、值为主文字，标签统一宽度（订单默认 84px）、值从固定起点开始；标签和值顶端对齐、行高统一为 24px，复制按钮与字段值对齐，不用空格补齐标签；短字段两列，长编号、文案、失败原因跨列或换行。不可将只读值画成输入框。
- 分节标题可用 3×12px 蓝色竖线，标题下留 12–16px，并以浅分割线区分。不要把竖线拉成整段高度。
- 关键金额可用主色加粗；图像、视频、状态章只在业务需要时出现。流程日志等次级内容可折叠，展开后有实际内容。
- 只读详情无保存按钮；只有业务动作时才使用底栏。关闭清理临时展开项，进入关联对象时保持返回路径清楚。

## 8. 新增、编辑与分步表单

- 新增与编辑共用主体，标题明确模式；普通表单 640–720px，默认 720px。表单标签在上，标签与控件间距 8px；字段间距 20px，分组间距 24px。
- 使用 Ant Design `Form` 处理校验与错误占位，相关短字段两列、列间 24px；长文案、说明、上传或规则表可占整行。两列控件等宽且顶端对齐。
- 必填星号在标签前；辅助说明 12/18，常驻帮助靠近字段，错误在字段下方并占自然高度。不要绝对定位错误文字、覆盖下一字段，或用隐藏输入产生额外空框。
- 只读与禁用区分：不可编辑的展示值优先文本；暂不可用的控件禁用并说明条件。例如先选拍摄点再启用航线，上游变化时清空失效的下游值及错误。
- 上传封面默认横向约 300×160px、浅蓝底和细边框，使用 Ant Design `Upload`；已选状态显示文件或缩略图，可移除和更换。说明支持格式和用途；校验错误与上传区绑定。没有上传后端时只保存本地预览或文件名，不伪称已上传服务器。
- 多行输入默认 4 行，必要时显示字数；数字与金额使用 `InputNumber` 并明确单位，日期用日期组件，枚举用选择组件。
- 多类型表单可用头部页签；分步表单在页签下显示步骤条，距表单约 28px。步骤标题描述任务，例如基础信息、拍摄攻略、套餐配置。
- 下一步校验当前步骤并定位首个错误；上一步保留输入。发布校验全部步骤并跳到首个出错步骤。切换类型保留通用字段，清理不适用配置。
- 底栏内边距 `12px 24px`、浅顶分割线、按钮右对齐、间距 8px。普通顺序「取消」「保存」；分步按需为「存草稿」「取消」「上一步」「下一步 / 发布」。
- 草稿允许未填必填项，需能恢复；没有草稿需求时不要增加草稿按钮。取消后重新新增不得残留临时输入，编辑另一记录时不得沿用上次错误。
- 提交中显示加载并防重复；成功反馈、更新 Mock 并关闭或进入结果。失败保留输入、说明原因与恢复方式。不可逆业务操作另设确认。

## 9. 反馈、状态与可访问性

| 状态 | 要求 |
| --- | --- |
| 加载 | 保留结构，使用表格加载或骨架；提交按钮显示加载 |
| 首次无数据 | 明确无记录；有权限且可创建时提供创建入口 |
| 筛选无结果 | 文案说明无匹配项，提供重置，不假装系统无数据 |
| 失败 | 明确失败对象与恢复动作，保留可恢复输入 |
| 禁用 | 使用组件禁用态，必要时解释原因，不仅改变颜色 |
| 悬停 / 焦点 | 保留组件反馈；键盘焦点有可见轮廓，不移除 outline 而无替代 |
| 成功 | 简短反馈并在列表、状态或详情中反映真实变化 |

- 使用语义化组件、标签关联、具名图标按钮；Tab 顺序与视觉顺序一致。弹层自动管理焦点、Esc 关闭与关闭后焦点返回；交互不要只支持鼠标悬停。
- 不用颜色单独区分状态；正文保持足够对比，弱文字只承载辅助信息。焦点建议 2px 主色轮廓和 2px 间隔；尊重减少动画的系统设置。
- 确认弹窗通常 440px，含长说明或文本域时约 600px；原型使用组件的标准层级，不用手写高 z-index 盖住抽屉。

## 10. 实现与交付

样式优先级：已有公共组件 → 全局 Token → 组件 Token → 页面作用域 CSS。需要焦点、键盘、弹层、上传、表单或表格能力时使用真实 Ant Design 组件，避免样式化 div 仿制。

交付前按 [页面验收清单](ui-checklist.md) 检查。构建与交互验证通过后，需分享时运行 `npm run export:html` 生成离线单文件；只在用户要求且目标已配置时发布到查看器。单独页面、导出 HTML 和查看器发布默认都保留业务导航，避免发布脚本擅自改版式。
