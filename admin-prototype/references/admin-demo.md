# 后台原型设计规范

优先级：用户要求 → 目标项目约定与设计稿 → 本规范 → Ant Design 默认值。已有项目沿用其目录及组件，仅调整本次需求与必要依赖。新模板使用 React、TypeScript、Vite、Ant Design、Hash 路由、本地 Mock 和相对资源路径。

## 设计参数

可执行参数的唯一来源是用户已确认的 `templates/admin/design/system.json`，初始化后位于项目 `design/system.json`。后续新建默认沿用该方案。`src/design/system.tsx` 将参数转换为 Ant Design 主题和 CSS 变量。不要在规范、CSS 和 JSX 中重复维护相同的数值。

以后调整颜色、字体、间距或布局，修改相应设计配置并运行 `npm run design:check`，再在真实业务页面核对。`design/schema.mjs` 维护参数结构及范围。主色默认由 Ant Design 派生交互色；需要组件独有尺寸时使用明确的组件参数。自定义字体需在本机可用或随资源打包，不引入 CDN。

## 页面与布局

页面保留清楚的业务标题和主要操作。导航选中项跟随路由，折叠后仍能识别菜单。外壳由 `src/layout/AdminShell.tsx` 管理，业务路由单独维护。顶部栏、导航、内容区尺寸均读取设计配置；发布到查看器隐藏业务侧栏，独立后台保留导航。

列表按筛选卡、列表卡组织；筛选极少时可单卡。统计只在业务需要时出现，收起后保留展开入口。表格内部滚动时分页位置稳定；选择整页滚动时取消表格纵向限高。筛选区域可以换行，宽表在表格内横向滚动，内容不撑开页面。

## 列表与查询

- 紧凑搜索复用 `CompactSearch`，由输入框及紧贴的主色图标按钮组成，宽高及圆角读取公共参数。提示语说明查询范围，下拉占位写字段名称。有查询按钮时点击或 Enter 生效；无按钮时可即时筛选。重置清理当前筛选组条件并回到首页。
- 表格使用 Ant Design Table，金额右对齐并统一小数位，状态使用文字加颜色，长文本可查看全文。列宽按内容设置，长文本限制可读宽度；操作列固定右侧，根据操作数量收紧。显式列宽之和与 `scroll.x` 匹配，不通过隐藏全页溢出来修复。
- 操作复用 `TableActions`，过多操作进入具名的更多菜单。分页显示总数，筛选或页容量变化后落在有效页，切换容量立即重新渲染。

## 详情与表单

- 普通详情使用右抽屉，复杂明细可独立页。已有抽屉标题时，正文从分节信息开始；对象名称和状态放字段区。独立页有返回、对象标识、摘要与明细层级。
- 抽屉复用 `DesignDrawer`，读取表单或详情宽度，并限制不超过视口。正文独立滚动；有提交操作时底栏固定，滚动到底也不遮挡内容。抽屉背景、边距和底栏阴影读取参数。
- 表单标签位置、字段列数及间距读取配置；间距由字段项统一控制，不叠加相邻上下 margin。长内容独占一行，错误提示自然撑开。新增及编辑共用表单，上游变化清理失效下游值。
- 只读详情显示文本，标签与值顶端对齐，标签保持统一宽度；长编号或说明可换行、跨列。分节及字段只由各自一层控制留白，不叠加 Descriptions 默认间距和段落 margin。
- 保存、草稿、步骤、确认等操作由业务需要决定。提交后更新 Mock 与界面，重复打开状态正确。详情与评审入口复用真实组件，不另造外观相似的实现。

## 扩展与验收

组件入口及扩展约定见[组件约定](components.md)。新增公共设计值先登记 `design/system.json` 与 `design/schema.mjs`，再接入主题或 CSS 变量；新增组件补使用规则和实现，并在实际页面核对状态。纯业务特例保留在模块内部，不扩大公共参数。

保留键盘焦点、图标按钮名称、关闭和焦点返回。核对实际视口、长文本、空数据、错误和禁用态，按[验收清单](ui-checklist.md)检查。独立分享使用 `npm run export:html`；查看器发布可选。
