# 后台原型设计规范

优先级：用户要求 → 目标项目约定与设计稿 → 本规范 → Ant Design 默认值。已有项目沿用原组件和目录；新模板使用 React + TypeScript + Vite + Ant Design、Hash 路由、本地 Mock 和相对资源路径。入口用 `ConfigProvider` 管理 Token，不依赖 CDN 或机器上的绝对路径。

## 视觉与页面框架

| 项目 | 默认值 |
| --- | --- |
| 颜色 | 主色 `#2776FF`，正文 `#303338`，次文字 `#696C70`，页面 `#F2F4F7`，白卡 `#FFFFFF` |
| 字体 | 中文系统字体；正文 14/22，辅助 12/18，页面标题 18/24，抽屉标题 16/24 |
| 几何 | 控件高 32px、圆角 2px；白卡圆角 4px；常用间距 8/12/16/20/24px |
| 外壳 | 黑色侧栏展开 220px、收起 80px；顶栏 58px；主体左右和底部 20px |

一页保留一个清楚的业务标题和一个主要操作。侧栏选中项跟随路由，折叠后仍可识别菜单。工作区使用浅灰底与白卡分层；不添加无业务意义的指标、装饰或大标题。桌面视口重点核对 1440、1600、1920px：筛选区可换行，宽表在表格内横向滚动，内容不撑开页面。

## 列表与查询

- 默认采用筛选卡与列表卡：筛选卡至少 64px 高、内边距约 12px 16px；列表卡的 56px 工具行放标题及主操作，下面是表格和右对齐分页。筛选极少时可用单卡。确有汇总需求时，在两卡之间放可收起统计卡，收起后保留展开入口。
- 查询输入框带主色前置搜索图标，提示语写「查询订单号、手机号」等范围；下拉占位写字段名，不加「全部」。有查询按钮时点击或 Enter 后生效；没有按钮时可即时筛选。重置只清理当前筛选组管理的条件，并回到第 1 页。
- 表格使用 Ant Design `Table`：浅灰表头、水平分割线，金额右对齐并统一小数位，长文本有悬浮提示或详情。状态由文字加颜色表达。操作列固定右侧，为列宽总和配置 `scroll.x`，不能靠全局隐藏溢出。操作多于三项时收进具名的更多菜单。
- 分页显示总数；筛选和页容量变化时保持有效页。空数据、无匹配结果、禁用动作与失败操作都给出可理解的反馈。

## 详情与表单

- 普通详情用右抽屉，复杂明细可用独立页。详情抽屉已有标题时，正文从分节信息开始；对象名称和状态放在字段区，不叠加大标题。独立页保留返回、对象标识、摘要和明细层级。
- 抽屉标题区至少 56px，可用浅蓝至白渐变；正文独立滚动，底栏固定且不遮挡内容。普通详情约 600px，密集订单约 800px，表单约 720px，宽度不超过视口。
- 两列 `Descriptions` 的标签为次文字，固定宽度（订单可从 84px 起），文字两端对齐；值从同一起点开始。标签和值顶端对齐，长编号和说明可跨列或换行。分节标题可用短蓝色竖线。只读字段显示文本，不伪装成输入框。
- 新增和编辑共用表单主体，标签在上、错误在字段下自然撑开；相关短字段两列，长内容独占一行。上游字段变化要清理失效的下游值。取消、保存、草稿、步骤和确认操作只在业务确实需要时出现，提交后更新 Mock 与界面。
- 彩色摘要区的时间、状态和辅助文字保持可读；筛选若改变摘要范围，明细也同步变化。详情抽屉与独立评审页复用同一真实组件，按路由决定是否显示后台外壳、背景和遮罩。

## 验收与分享

保留键盘焦点、图标按钮名称、弹层关闭和焦点返回。优先复用现有组件，再用 Token 和局部 CSS；不复制一套外观相同的详情实现。交付前按[验收清单](ui-checklist.md)检查。新模板的离线分享命令为 `npm run export:html`；查看器发布是可选集成。
